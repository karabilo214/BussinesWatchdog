## Админка

### Сайт и страницы
- [x] **Главная страница редактируется из админки.** (Step 121) Сейчас обычные (созданные владельцем) страницы редактируются, а системные — главная, тарифы, обратная связь — нет: данные не загружаются. Решение владельца (2026-10-13): главную открыть для редактирования; «Тарифы» и «Обратная связь» меняются только через код — в админке у них не должно быть сломанного редактора (только просмотр/настройки меню или понятная пометка «редактируется в коде»).
- [x] **Визуальный редактор вместо HTML-поля.** (Step 122, ADR 0045) Полноценный редактор для не-программистов, с подключённым Tailwind (предпросмотр в стилях сайта). Выбор редактора — через ADR.
- [x] **Готовые шаблоны блоков и секций** (Step 123, ADR 0046) (герой, преимущества, цены, FAQ, CTA и т. п.), вставляемые в страницу из редактора.
- [x] **Отдельный раздел «Шаблоны блоков»** (Step 124) — создание и редактирование этих шаблонов.
- [x] **Версии страниц** архив старых версий, нужна возможность удалить, если это не документация (Step 139)

## Публичный сайт
- [x] **Тарифы: поле количества дополнительных магазинов** (с пересчётом цены), как в кабинете. (Step 138)
- [x] **Публичная предварительная проверка магазина по URL** (Step 145, ADR 0058): страница на публичном сайте, где посетитель вводит HTTPS-адрес магазина без регистрации, подтверждения владения, API-ключей, плагина или App. Запускать одноразовую безопасную browser-диагностику только по публичным страницам: доступность, TLS/DNS/redirect, базовый путь storefront → товар/корзина/checkout, WAF/CAPTCHA/login stop, критичные console/network ошибки. Показывать краткий verdict, шаги и скриншоты; скриншоты и артефакты удалять через 5 минут, чтобы не забивать диск. Результат не является мониторингом, не даёт financial/payment coverage, не создаёт incidents/findings и не проверяет реальные оплаты. Требуются SSRF/abuse-ограничения: обязательная CAPTCHA до запуска проверки, только public HTTPS, запрет private IP/localhost/metadata, один и тот же нормализованный host/origin можно проверять не чаще 1 раза в 30 дней, один IP может проверить только 1 сайт за 10 дней, отдельный короткий лимит на submit-попытки с IP, короткие timeout, без произвольного JS/селекторов от пользователя и без опасных mutation-действий.

## Решения по ADR (2026-10-16)
- [x] **Скрипт наблюдения Shopware через сам магазин, как в WooCommerce** (Step 160, ADR 0062): браузер отправляет этапы только на адрес App в магазине (App Scripts, custom endpoint), магазин хранит их в своей таблице App, сервис забирает через Admin API; прямой путь браузера к сервису и картинка 1×1 убираются. Сначала spike на Shopware 6.6/6.7 (одновременные запросы, права на запись, кеш), затем реализация, e2e в Docker, новый документ для юриста.
- [x] **Настройка владельца компании «показывать суммы»** (Step 161, ADR 0018): владелец tenant решает, видят ли денежные суммы расхождений остальные роли команды (обзор, инциденты, находки); проверка и на бэкенде.
- [x] **Разделить тестовый и боевой режим в суммах и инцидентах** (Step 162, ADR 0018): инциденты тестового режима провайдеров не смешиваются с боевыми в суммах «Обзора».
- [ ] ~~**Подключение Stripe в один клик из кабинета**~~ (ADR 0020; Step 163 — код, Step 185 — удалён): Не доступно для Украины: Stripe не даёт завершить настройку аккаунта платформы без зарегистрированного бизнеса в Германии, а без этого не работают ни авторизация клиента через кнопку, ни External test. Если будет зарегистрированная компания в Германии, можно вернуться к этому пункту. Код Stripe App OAuth (Step 163, коммит `db0bd13`) удалён; клиент подключает Stripe ограниченным ключом (restricted key).
- [x] **Предупреждение на «Обзоре» кабинета, если у пользователя не включена MFA** (Step 164, ADR 0021): заметный блок «MFA не подключена — вы сильно рискуете»; то же уведомление получает новый владелец после передачи владения.
- [x] **Сброс MFA клиента** (Step 165, ADR 0021): в админке у каждого пользователя клиента кнопка «Отключить MFA» (сотрудник платформы, step-up, аудит); в кабинете владелец компании может сбросить MFA любого сотрудника своей команды (аудит, письмо пользователю).
- [x] **Скидка, ограниченная тарифами, сгорает при смене тарифа** (Step 166, ADR 0037 п. 6): при переходе на тариф, который скидка не покрывает, оставшиеся периоды списываются и при возврате не восстанавливаются; смена только числа дополнительных магазинов и скидки без ограничения тарифов не затрагиваются.
- [x] **Полная пауза магазинов сверх лимита тарифа** (Step 167, ADR 0037 п. 7): кроме браузерных проверок останавливаются приём данных, синхронизация провайдеров и сверка; история и настройки сохраняются; в кабинете «на паузе», денежные результаты `unknown`, без инцидентов свежести; после снятия паузы — догрузка данных через окно перепроверки коннекторов.
- [x] **Загрузка картинок в редакторе страниц** (Step 169, ADR 0045, ADR 0063): загрузка файла из админки вместо ввода https-адреса; хранение, ограничения размера и типа, очистка метаданных.
- [x] **Подсветка кода в режиме «HTML-код»** редактора страниц (Step 171, ADR 0045).
- [x] **«Шаблоны блоков» убрать из общего меню админки** и перенести в раздел страниц сайта (Step 172, ADR 0045).
- [x] **Роли и права сотрудников платформы настраиваются в админке** (Step 173, ADR 0046, ADR 0064): владелец платформы сам назначает каждому сотруднику, что ему можно (контент, клиенты, оплаты, возвраты, аудит, сервис, настройки и т. д.), вместо жёстких ролей в коде. Владелец всегда имеет все права, управление сотрудниками — только владелец, изменения с повторным подтверждением кода и в аудите.
- [ ] **Расширить встроенный набор шаблонов блоков** (ADR 0046): много разных блоков, чтобы страницы собирались легко (отзывы, логотипы, сравнение, контакты и др.) — состав уточнить с владельцем.
- [x] **Напоминания клиентам: выбор получателей, редактируемые шаблоны, полная история** (Step 174, ADR 0047): сотрудник выбирает получателей среди участников компании; шаблон (подписка, оплата, другое) редактируется перед отправкой, кнопки «Сохранить шаблон» и «Отправить»; каждое отправленное письмо сохраняется целиком (кто, когда, кому, тема и текст) и видно в карточке клиента.
- [x] **Действия поддержки в магазинах клиента** (Step 175, ADR 0048): перезапуск браузерной проверки и принятие/закрытие инцидента за клиента из админки (с причиной, аудит); действия сотрудника не расходуют лимиты и счётчики клиента.
- [x] **Аудит админки — только изменения** (Step 176, ADR 0048): убрать запись просмотра магазина (`tenant.store_viewed`), записывать все изменяющие действия (POST/PUT/PATCH/DELETE) в аудит платформы и организации.
- [x] **Изменение ролей и удаление участников команды клиента из админки** (Step 177, ADR 0048): по просьбе клиента, с причиной и аудитом; роль владельца — только через передачу владения.
- [x] **Шаблоны ответов на обращения редактируются в админке** (Step 178, ADR 0049): кнопки «Сохранить шаблон» и «Отправить», как у напоминаний клиентам.
- [x] **Автор может править свою заметку в обращении** (Step 178, ADR 0049): в аудите — текст до и после.
- [x] **Оповещение о проблеме в «Сервисе» на e-mail ответственного** (Step 179, ADR 0051): адрес задаётся в конфиге (env), письмо при переходе общего состояния в «проблема» и при восстановлении, без повторов на каждой проверке; переменную описать в README.
- [x] **Сброс аутентификатора сотрудника платформы из админки** (Step 180, ADR 0052): кнопка у владельца платформы для сотрудников, кроме владельцев (причина, код, аудит, завершение сессий); аутентификатор владельца — только через `platform:reset-mfa` на сервере.
- [x] **Адрес приглашённого сотрудника в аудите — открыто** (Step 180, ADR 0052), вместо отпечатка.
- [x] **Срок хранения аудита платформы — 2 года** (Step 181, ADR 0053): ежедневное удаление записей старше 2 лет, срок в конфиге (env), описать в README.
- [x] **Пауза во время окна обслуживания** (Step 182, ADR 0054): на время активного окна автоматически останавливаются плановые браузерные проверки, оценка свежести коннекторов и уведомления клиентам; разрывы данных, начавшиеся во время окна, не создают инцидентов сразу после его окончания; биллинг не останавливается.
- [x] **Баннер окна обслуживания на публичном сайте** (Step 183, ADR 0054), на языке страницы.
- [x] ~~**Журнал веб-сервера для `/api/v1/observe/*`**~~ (ADR 0057) — не нужно: прямой путь браузера к сервису убран (Step 160, ADR 0062).
