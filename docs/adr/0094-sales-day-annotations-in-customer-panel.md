# ADR 0094: Пометки дней в кабинете клиента

Дата: 2026-10-30. Статус: принято как продолжение задачи 12.B, ADR 0090/0092/0093. Step 327.

В настройках магазина клиент с правом stores.manage отмечает прошедший/текущий локальный день как акцию или праздник и может удалить такую пометку. Предел — последние 28 завершённых локальных дат и сегодня, отдельно live/test. Член с stores.read видит сохранённые пометки. Автоматические pause/data_gap показаны только для чтения; инциденты не раскрываются через этот API. Свободного текста и данных покупателя нет.

Контракт GET/PUT `/api/v1/stores/{store_id}/sales-exclusions` добавляется до кода. PUT задаёт состояние только одного ключа date/kind/mode; блокировка строки магазина сохраняет остальные пометки при параллельных действиях клиента и scheduler. Повтор того же действия не создаёт дубликат или повторный аудит. Удаление ручной пометки не меняет покрытие и не удаляет автоматические причины непригодности. UTC-границы рассчитывает сервер в часовом поясе магазина, клиент их не задаёт; сохранённые границы остаются привязаны к прежнему часовому поясу при его изменении.

Норма и прогрев уже читают эти пометки. Интерфейс не включает тревоги, не показывает готовую норму и не обещает календарный срок её сбора. Это подготовка условий сравнения, без изменения тарифов. Миграций нет: используется nullable JSONB из Step 324, новые строки журнала аудита совместимы со старым кодом.

Автоматический календарь DE остаётся отдельной частью: в модели магазина пока нет страны/земли для региональных праздников; подменять весь календарь Германии одним часовым поясом нельзя. Здесь клиент может явно отметить известный праздник. Обработка праздников как воскресенья для будущего детектора, автоматический календарь, достаточность выборки и калибровка остаются открытыми. Никакие юридические тексты и production не меняются.
