# ADR 0029: Plans, entitlements and their enforcement

Status: implemented (Step 97); plan contents and prices await the owner

## Context

TZ §29/§29.1 and spec/panels/ADMIN-BACKEND.md §4: sold functions have stable feature codes and limits in immutable plan versions; availability is decided only on the server by an entitlement calculator from the subscription, a temporary override or a trial, and checked at every point (scheduling, detectors, ingestion of extra data, API, notifications, export). Unknown is not "everything included".

## Decisions

- **Tables** (from spec/database/platform-billing-extension.sql): `billing_plans`, `billing_plan_versions` (immutable once published: `entitlements` JSON with features and limits), `billing_prices` (per provider, mode, currency, interval), `subscriptions` (billing state of the tenant: trial/active/past_due/suspended/cancelled, plan code, entitlements snapshot, period), `entitlement_overrides` (temporary grants with reason and interval). Staff references stay nullable until the platform staff tables exist (admin step).
- **Catalog** (`App\Support\Billing\FeatureCatalog`): features `checkout_monitoring`, `payment_attempts_server`, `payment_attempts_script`, `money_reconciliation`, `order_outcomes`, `notifications_telegram`, `agency_workspace`; limits `max_active_stores`, `min_check_interval_minutes`, `retention_days`, `monthly_event_budget`, `manual_runs_per_day`. Entitlement JSON is validated against it; an unknown code is rejected.
- **Calculator** (`EntitlementCalculator`) follows the spec's priority: tenant deleting/deleted → no service; tenant suspended → paused (manual); paid period (status active/cancel scheduled until period end) → plan snapshot; active override → override (over the paid limits, never over a manual suspension); trial until its end; past_due within 7 days of grace → previous snapshot; otherwise expired/onboarding. The result carries the access state, reason codes, plan code/version, features and limits.
- **Enforcement mode** (`WATCHDOG_BILLING_ENFORCEMENT`, default `pilot`): until subscriptions are sold, every tenant is treated as a manually granted pilot with every feature and no limits — exactly today's behaviour, as TZ §29 allows for the P0 pilot ("entitlement выдаётся вручную"). With `enforce`, the calculator's result is applied. The calculator, the API and the checks run in both modes; only the outcome differs, so switching is a configuration change, not new code.
- **Checks wired now** (in `enforce` mode): browser check scheduling and manual runs (`checkout_monitoring`, minimum interval), payment attempt windows (`payment_attempts_server`; not projected and reported as not entitled), money reconciliation (`money_reconciliation`; findings `unknown` / `not_entitled`, never "ok"), Telegram channels (`notifications_telegram`), store creation (`max_active_stores`). Plugin-side switching through the heartbeat response follows with the checkout script (layer 2).
- **API**: `GET /api/v1/entitlements` returns the current tenant's access state, plan, features (each with `included` and a reason) and limits, so the dashboard shows "not in your plan" instead of "all good".
- **Price depends on the number of stores** (owner, 2026-10-11: one store and ten stores differ in price and load). Both models are supported and the owner picks per plan: (1) **tiers** — a plan includes N stores (`max_active_stores`); (2) **per extra store** — a plan version may have an `extra_store` price next to its `base` price, the subscription holds `extra_store_quantity` (Paddle sells it as an item quantity), and `max_active_stores` = included + bought (capped by `max_extra_stores`). Load-bound limits declared per store (`monthly_event_budget`, `manual_runs_per_day`) are multiplied by the resulting number of stores; the check frequency floor (`min_check_interval_minutes`) applies to every store.
- **Placeholder catalog**: `billing:seed-placeholder-plans` creates draft plans Free / Start / Pro marked as placeholders; nothing is published or sold until the owner sets contents and prices.
