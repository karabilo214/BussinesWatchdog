# ADR 0095: Явный регион календаря DE для подготовки нормы продаж

Дата: 2026-10-30. Статус: принято для подготовки нормы задачи 12.B; продолжение ADR 0090/0093/0094. Step 328.

Клиент явно выбирает землю Германии для календаря сравнения продаж; страна DE задаётся кодом DE-XX. По timezone, домену, адресу покупателя или IP регион не определяется. Местные исключения — Mariä Himmelfahrt/Friedensfest для BY, Fronleichnam для SN/TH — задаются отдельными флажками. Пустой список флажков означает, что местные исключения не выбраны; их применимость клиент проверяет для нужной местности. Это один выбранный рынок сравнения магазина, а не восстановление географии покупателей. Остальные страны и смешанная география пока не поддерживаются этим автоматическим календарём; ручные пометки остаются.

Локальный версионированный справочник покрывает только 2026–2027, без сетевых запросов при работе магазина и без экстраполяции законодательства на непроверенные годы. Основа: [Bundesbank 2027](https://www.bundesbank.de/resource/blob/749314/2341c4cfcb5d78fb9a96b50f2b6aa528/mL/feiertage-in-deutschland-1-data.pdf), [официальный календарь Berlin 2026/2027](https://www.berlin.de/tourismus/infos/1887651-1721039-feiertage-schulferien.html), [BayFTG](https://www.gesetze-bayern.de/Content/Document/BayFTG/True), [SächsSFG](https://www.revosax.sachsen.de/vorschrift/3997-SaechsSFG?follow_successor=no), [Brandenburg FTG](https://bravors.brandenburg.de/gesetze/ftg_2015). Речь о календарных праздниках, не банковских сроках: 24/31 декабря не объявляются общими праздниками из-за закрытия Bundesbank. Остальные специальные дни клиент может пометить вручную. Новые годы/изменения требуют обновления справочника в репозитории и тестов перед обычным выпуском.

Автоматический праздник не записывается как ручная JSONB-пометка: он вычисляется для локальной даты в текущем выбранном регионе, применяется к live/test, не удаляется через API ручных исключений. Исторические сохранённые ручные границы не меняются. Праздник исключён из обычных образцов прогрева, его comparison_weekday=7 готовит правило «праздник как воскресенье» ADR 0090. Сама статистическая норма и сравнение с воскресными образцами ещё не вычисляются; это метаданные для следующего этапа. Покрытие заказов не меняется и тревоги не включаются.

При отсутствии выбранного региона счётчик пригодных дней остаётся предварительным, как в Step 325, с явным calendar not_configured. При выбранном регионе, но неизвестном годе дата непригодна для нормы и comparison_weekday неизвестен. Общая baseline_state остаётся unknown и alerts_enabled=false при любой ступени. Календарь не подтверждает достаточность выборки или покрытие денег.

Конфигурация в существующем stores.settings.sales_calendar: region, local_holidays, version. Миграций нет, прежний код игнорирует добавочный ключ. GET sales-exclusions добавляет calendar/holidays; PUT sales-calendar требует stores.manage и If-Match отдельной версии календаря (начальная 1). Чужой tenant/store скрыт; запись под блокировкой сохраняет соседние settings и пометки, смена настройки аудируется атомарно. Конфликт — 409 без потери данных, повтор идентичного состояния — без новой версии/аудита. Изменение региона сразу пересчитывает диагностику; сброс в null возвращает not_configured. Юридические страницы, тарифы и production не меняются.

Для UTC-бакета, пересекающего местную полночь, проверяются все затронутые локальные даты; он не является одним локальным образцом (local_day_boundary, comparison_weekday=null). Полный локальный день остаётся одним образцом, в том числе при DST; точная правая граница следующего дня не включает этот день в интервал [from,to). Это предотвращает потерю начала праздника при часовых поясах с получасовым/45-минутным смещением.
