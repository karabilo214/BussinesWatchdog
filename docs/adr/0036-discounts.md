# ADR 0036: Discounts managed in the owner panel

Status: implemented (Step 105); stacking by owner decision 2026-10-12 (Step 106) replaces the one-discount rule

## Context

Owner 2026-10-12: discounts are part of the fully configurable commercial setup in the owner panel. Paddle discounts (checked in the sandbox): percentage (decimal string) or flat amount in minor units with currency, `recur` + `maximum_recurring_intervals` (null = forever), `usage_limit`, `expires_at`, archiving by status; a server-created transaction accepts `discount_id` and the discount moves to the subscription for its duration.

## Decisions

1. **Kinds and terms**: percentage (stored in basis points, 0.01–100 %) or flat amount with currency; duration one payment, 1–1000 billing periods or forever; optional usage limit, start and end; plans (none = all plans).
2. **Audience**: promo code (entered by the customer, 3–32 characters, case-insensitive), chosen organisations (applied without a code; found by name in the panel) or an offer for everyone buying the chosen plans.
3. **Applied only by our server**: discounts are created in Paddle with `enabled_for_checkout: false`, so Paddle's checkout window does not accept codes; our checkout checks the discount (active, started, not expired, plan, flat-amount currency equals the price currency, confirmed uses below the limit) and passes `discount_id` with the transaction it creates. Paddle's own `usage_limit` and `expires_at` are set as a second guard. The browser's code or amounts are never trusted.
4. **Stacking (owner 2026-10-12)**: the best public offer, then the organisation's own discount (the best one), then an entered promo code all apply — one after another, each on the amount left by the previous one (percentages rounded half up to a minor unit, flat amounts never below zero; e.g. 100 € − 20 % = 80 → − 10 % = 72 → − 5 € = 67 €). A code that does not apply is an error. Paddle accepts one discount per transaction and one per subscription, so our server sends one combined flat discount (sandbox-verified: a flat discount lowers a tax-inclusive total by exactly its amount): for the purchase a one-time discount on the transaction; for each renewal a discount `recur: true, maximum_recurring_intervals: 1` set on the subscription with `effective_from: next_billing_period` (a one-time discount is refused for subscriptions). Each discount keeps its own duration counted from the purchase (`billing_discount_grants`: periods total/used); `billing:plan-discounts` (every 15 minutes) computes the next period from the discounts still running as soon as the current period is known and sets it at Paddle; a failed call is retried. Every period is recorded in `billing_discount_applications` + `billing_discount_application_lines`: amount before, each discount with the amount before it, its saving and the amount after it, the total, the Paddle discount, the status — shown in the owner panel ("История скидок"). Archiving or the end date of a discount stops new purchases only; purchases that got it keep it for its duration.
5. **Customer view**: `/api/v1/billing/discounts/check` (owner, 10 per minute) tells whether a code applies to a price; the catalog lists the best public offer and the organisation's own discount per plan; the subscription page shows every discount with its saving in order, the crossed-out total and the first payment after discounts (BigInt, half up) and says Paddle shows the final total with taxes. Uses are counted from paid purchases that got the discount.
6. **Changes**: creating, changing (name, customer text, plans, organisations, start, end, usage limit) and archiving need a reason and an authenticator code and are audited; the amount, audience and duration of an existing discount never change — create a new one. Archiving stops new purchases; subscriptions that have the discount keep it until it ends.
7. Verified in the Paddle sandbox: promo code created in the panel (20 %, 2 periods, Start only, 5 uses), bought with Paddle's test card: transaction total 22.40 € instead of 28.00 €, `times_used` 1, the subscription carries the discount for two monthly periods.
8. Stacking verified in the Paddle sandbox (Step 106): offer 10 % forever + promo code 20 % for 2 periods created in the panel, bought with Paddle's test card: 28.00 € → 25.20 € → 20.16 € paid; `billing:plan-discounts` set the second period's combined discount and Paddle's next transaction shows 20.16 €; a second run changed nothing.
