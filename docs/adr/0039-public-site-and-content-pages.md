# ADR 0039: Public site rendered on the server, content pages and the contact form

Status: implemented (Step 111); points 7–12 accepted by the owner on 2026-10-12 as they are for now

## Context

spec/panels/PUBLIC-SUBSCRIPTION-FRONTEND.md §1, §2, §3, §8 and ADMIN-BACKEND.md (public content endpoints). The owner asked (2026-10-12): the home page built in the owner panel with an HTML editor; a pricing page; other pages on a dynamic route, created in the panel with an HTML editor and a slug set at creation, nested `slug/slug` up to two levels (terms, guarantees, about the company live there); a contact page with a form whose messages are read in the panel; server-side rendering is mandatory. Owner choices: HTML code with a live preview (not a visual editor); one slug with a text per language; messages stored and announced by email; draft → publish with every published version kept.

## Decisions

1. **Rendering**: the public site is rendered by Laravel with Blade on every request (SSR), complete HTML without JavaScript; no Node at runtime. `apps/frontend/public` no longer prerenders Vue pages with vite-ssg (ADR 0017 superseded for this package): it only builds the site stylesheet (Tailwind + frozen palette) into `apps/backend/public/site` with a Vite manifest read by `SiteAssets`. Without the build the site works unstyled.
2. **Addresses**: `/{ru|en|de}`, `/{lang}/pricing`, `/{lang}/contact`, `/{lang}/{slug}` and `/{lang}/{slug}/{slug}`; `/` redirects to the first language of `Accept-Language` we have (otherwise `en`). Canonical and `hreflang` alternates only for languages with published content; unknown paths answer a 404 page in the site layout.
3. **Pages**: `public_pages` (kind `home`, `pricing`, `contact` — system pages created by the migration, cannot be deleted — or `page`), slug of lowercase latin letters, digits and single hyphens (≤ 60), fixed at creation; a parent must be a top-level ordinary page (two levels); the full path is unique among pages that are not archived. Menu `none` / `header` / `footer` and an order; menu labels are the published titles of the language, a page without a published text in that language is not in its menu.
4. **Versions**: `public_page_versions` per page and language: at most one draft and one published version (partial unique indexes). Publishing retires the previous version — it never changes and stays in the history with who published it and when; restoring copies an old version into the draft; unpublishing retires without a replacement (an ordinary page answers 404, a system page falls back to its built-in text); archiving an ordinary page (no child pages) retires its versions, drops drafts and frees the path. Every change is in `platform_audit_log`; publish, unpublish and archive need a reason; the audit of a publication keeps the version, the previous version and the content hash.
5. **HTML**: sanitized on save and on preview with Symfony HtmlSanitizer: safe elements, `class` and `id` allowed; scripts, frames, forms and form controls, event handlers and `style` removed; links only http(s), mailto, tel and relative (`rel="noopener noreferrer"` forced); images only https or relative. The site stylesheet offers ready classes for content (`lead`, `hero`, `band`, `grid-2`, `grid-3`, `card`, `button`, `note`, …). The preview is the real site layout (noindex) in a sandboxed frame without scripts; its stylesheet is inlined so it does not depend on the panel reaching the site origin.
6. **Pricing**: plans and prices only from the published catalog of the current Paddle mode (`BillingCatalog`); period and currency switches show only published prices, no conversion; a yearly price is shown as the yearly charge with “about X per month” and a saving only against a monthly price of the same plan and currency; tax wording from the price's tax behaviour; amounts formatted from minor units without floats. Automatic discounts are not shown (they depend on the organisation). “Choose plan” leads to the billing page of the customer account (there is no public sign-up page yet).
7. **Example plans** (accepted for now): placeholder plans (`billing:seed-placeholder-plans`) appear on the pricing page only in test mode, marked “Example plan”, under the test-mode notice; in live mode they are hidden.
8. **Who does what** (accepted for now): `content.manage` (pages) — platform owner only; `contacts.read` — owner, admin, support; `contacts.manage` (status, note) — owner and support. Publishing a page needs a reason but no authenticator code (unlike prices and discounts).
9. **Contact form** (accepted for now): name, email, optional company, message (10–5000 characters); a hidden honeypot field (filled → pretend success, store nothing); at most 5 messages per hour per IP (`WATCHDOG_SITE_CONTACT_PER_HOUR`); the IP is not stored; the message is stored as plain text like account emails (not in the keyring). Validation errors are listed above the form and next to each field; the page is `no-store`.
10. **Notification** (accepted for now): `site:contact-notify` (every minute) emails new messages to `WATCHDOG_SITE_CONTACT_NOTIFY` or, if empty, to every active platform owner; the form never waits for the mail server; a failed send is retried for three days.
11. **Retention** (accepted for now): closed messages are deleted 365 days after closing (`site:contact-purge`, daily; `WATCHDOG_SITE_CONTACT_RETENTION_DAYS`); open messages are kept.
12. **Caching** (accepted for now): public pages are sent with `Cache-Control: public, max-age=60` (`WATCHDOG_SITE_CACHE_SECONDS`), so a change or removal may take up to a minute to reach a visitor who opened the page recently; no session cookie on these pages.
13. **Not in this step**: binding sign-up/checkout acceptance to legal page versions (`policy_versions`), image upload (images by https URL only), sitemap.xml/robots.txt, a public sign-up page, a visual editor, SEO fields beyond title/description.

## Amendment (2026-10-13, Step 121, owner's decision)

14. **System pages**: the home page is edited in the owner panel like an ordinary page; its built-in text is no longer separate Blade markup but ordinary page HTML built from the translations with the content classes (`resources/views/site/builtin/home.blade.php`, `SiteDefaults`). The site shows it until a version is published, and the editor starts from it, so the owner edits exactly what visitors see. An empty home body still means the built-in text. The pricing and contact pages are changed only in code: the API refuses drafts, publication, preview and restore for them (409 `edited_in_code`), the site ignores any stored versions of them (text and menu label come from the translations), and the panel shows only their menu settings with an “edited in code” note. Discarding a draft and unpublishing stay allowed so leftovers can be cleared.

## Amendment (2026-10-13, Step 139, owner's backlog)

15. **Deleting old versions**: an old (retired) version of a page can be deleted for good with a reason (audited with version and content hash). The published version and drafts cannot be deleted. Versions of a page marked as a legal document, and any version a customer accepted (`policy_acceptances`), are never deleted — they are the evidence of what was agreed (ADR 0042). Version numbers are not reused for the history that remains.
