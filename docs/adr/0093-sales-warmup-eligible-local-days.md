# ADR 0093: Пригодные локальные дни и диагностические ступени прогрева

Дата: 2026-10-30. Статус: принято для внутренней диагностики; продолжение решения владельца ADR 0090 и слоя покрытия ADR 0092. Задача 12.B, Step 325.

Прогрев созданных заказов считается отдельно от paid-маркеров и независимых capture. `SalesWarmup` проверяет последние 28 завершённых календарных дней в часовом поясе магазина на момент конца запроса `sales:history`. Текущий неполный день не считается; сутки DST имеют фактические UTC-границы и дают один день независимо от 23/25 часов. Начало запрошенного почасового отчёта не сокращает горизонт прогрева.

Пригоден только целый день с непрерывным подтверждённым покрытием заказов после `first_observed_at` того источника, который дал соответствующий интервал. Это время фактического наблюдения, не дата заказа или начало backfill. Сначала каждый источник обрезается своим временем наблюдения, затем объединяются интервалы; повторные подключения не позволяют приписать старой подгрузке наблюдение нового источника. Разрыв любой длины, неприменённые проекции и отсутствие журнала не считаются нулевыми продажами и не дают пригодный день. День с известным исключением не входит в счётчик; live/test учитываются отдельно. Текущая пауза сама по себе не отменяет ранее пригодные дни: исключаются сохранённые дни паузы, а факт текущей приостановки по-прежнему учитывается в основном отчёте покрытия.

Ступени из ADR 0090: 0–6 — `collecting`, 7–13 — `stoppage_only`, 14–27 — `major_drop`, 28 — `full`. Отчёт возвращает число пригодных дней, следующую границу и сколько ещё пригодных дней требуется. Это количество данных для соответствующей будущей чувствительности; оно не является обещанием даты окончания прогрева, готовой нормой или включением тревог. Исключение или выход дня из скользящего окна может уменьшить ступень.

Внутренний JSON `sales:history` версии v3 получает `order_history_warmup` с перечнем дат, их покрытием и причинами исключения. Общие `baseline_state=unknown`, `warmup_stage=unverified_history`, `alerts_enabled=false` сохраняются: календарь праздников DE, интерфейс пометок акций, калибровка, достаточность числа заказов/выборки и собственно статистическая норма ещё не готовы. Даже `full` не разрешает детектор. Никакие суммы, идентификаторы покупателей/сеансов, внешние API или инциденты этим расчётом не создаются.

Уточнение хранения ADR 0092: финализатор обрезает журнал по началу локального дня магазина минус 28 календарных дней, сохраняя 28 завершённых дней и текущую часть дня. Прежняя граница «сейчас минус 28 суток» обрезала самый ранний день и делала 28 пригодных суток недостижимыми при обычном дневном запуске. Это небольшой запас технического журнала границ, а не увеличение окна статистической нормы; nullable JSONB и его версия v1 остаются совместимыми. Прошлое, уже обрезанное прежним кодом, не восстанавливается без нового полного чтения.

Миграций и API/event-контрактов нет; новое поле относится только к внутренней диагностической CLI. Пользовательские обещания, тарифы, юридические страницы и production не меняются. Следующий срез — интерфейс пометок и календарь DE, затем статистическая норма/калибровка; новые агрегатные окна и плагины остаются в бэклоге.
