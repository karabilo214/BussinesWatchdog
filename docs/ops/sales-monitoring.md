# Диагностика истории продаж задачи 12

Первый срез Step 323, ADR 0091. Это внутреннее чтение существующих проекций для подготовки нормы и калибровки. Детектор, пользовательский экран, автоматические уведомления и оценка потерь ещё не включены; тарифы не меняются.

Из `apps/backend` на Mac:

```sh
/opt/homebrew/opt/php@8.4/bin/php artisan sales:history --tenant=<tenant-uuid> --store=<store-uuid>
/opt/homebrew/opt/php@8.4/bin/php artisan sales:history --tenant=<tenant-uuid> --store=<store-uuid> --from=2026-10-29T00:00:00Z --to=2026-10-30T00:00:00Z --mode=live
```

В Docker PHP 8.4 используется тот же artisan command из каталога приложения. `--tenant` и `--store` обязательны и проверяются вместе. `--mode=live` по умолчанию, `test` — отдельный отчёт. Без дат — последние 28 суток до начала текущего UTC-часа. Явные даты — RFC3339 с секундой и смещением/`Z`; интервал `[from,to)`, положительный, не больше 28 суток, не в будущем. Все значения — идентификаторы своего тестового окружения, не примеры для запроса к production.

Вывод JSON содержит только идентификатор магазина, режим/часовой пояс, интервал, почасовые счётчики и причины непригодности для тревог; ссылок на заказы, transaction IDs и данных покупателей в нём нет. Границы часов UTC, локальная подпись с offset и днём недели магазина; два повторных часа DST различаются. Отметки оплаты магазина не называются независимыми списаниями; заказ с частичным capture тоже попадает в `orders_with_capture_observed`, поэтому это не число полностью оплаченных заказов.

Нулевой счётчик — ноль найденных наблюдений, **не** доказанное отсутствие продаж: `coverage=unknown`, `baseline_state=unknown`, `warmup_stage=unverified_history`, `alerts_enabled=false`. Свежий heartbeat описывает состояние источника сейчас, а не историческую полноту. Deleted/synthetic/test (для live) исключены, дубли проекций одного заказа после переподключения не увеличивают счётчик. Повторный запуск не меняет БД. Команда не вызывает провайдеров, не запускает покупки, не создаёт инциденты и не включена в cron.

Команда может читать большую историю внутри одного магазина: перед автоматизацией нужны измерения на реальном объёме и журнал исторического покрытия. Не использовать сегодняшний снимок как принятую норму; backfill и время первого заказа не запускают прогрев 7/14/28 дней. Следующий этап и пробелы наблюдения — [аудит](../checkout-monitoring-audit.md), задача 12.B бэклога.

Проверки:

```sh
cd apps/backend
/opt/homebrew/opt/php@8.4/bin/php artisan test --filter=SalesHistoryTest
DB_CONNECTION=pgsql DB_HOST=127.0.0.1 DB_DATABASE=business_watchdog_test /opt/homebrew/opt/php@8.4/bin/php artisan test --filter=SalesHistoryTest
```

PostgreSQL-команда использует локальную тестовую базу, принятую `make backend-test-pgsql`; до теста она должна существовать. Для backend-тестов использовать PHP 8.4 по AGENTS.md. Выкладка и любые изменения production — отдельная команда владельца.
