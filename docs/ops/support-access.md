# Доступ поддержки к магазину

Сотрудник платформы работает под своей учётной записью с правом `tenants.support`. Для подробных заказов, находок, проверок и инцидентов ему требуется разрешение владельца организации на конкретный магазин. Это относится и к владельцу платформы. Коммерческая сводка организации доступна по отдельным платформенным правам. Секреты интеграций не входят в разрешение.

1. В панели платформы откройте карточку клиента → «Доступ поддержки». Выберите магазин и категории данных, укажите основание. Сервис автоматически присвоит запросу единый сквозной номер вида `SUP-000001`; вводить его не нужно. Срок — 24 часа по умолчанию, максимум 72 часа с момента одобрения. Клиентский владелец также может создать запрос из «Настройки → Доступ поддержки», выбрав сотрудника поддержки из списка по имени (e-mail сотрудников клиенту не показывается).
2. О новом запросе владельцу организации приходит письмо со ссылкой на кабинет; повтор одинакового ожидающего запроса не создаёт нового письма. Только владелец одобряет или отклоняет запрос. Пока запрос ожидает решения, подробные данные недоступны. Для дополнительных категорий данных или нового срока нужен новый запрос и новое одобрение.
3. `read_diagnostics` открывает диагностику магазина; `read_artifacts` разрешает просмотр материалов; `request_recheck` разрешает повторно запустить существующий безопасный сценарий проверки. Запуск требует отдельного основания и сохраняет прежние ограничения браузерной проверки. Разрешение не позволяет экспортировать данные, входить от имени клиента или менять настройки.
4. Владелец организации может отозвать доступ в любой момент. Следующий запрос API и даже ранее выданная ссылка на материал проверяют актуальное разрешение. Страница сотрудника очищает загруженные подробности при обнаружении истечения или отзыва. Уже увиденную сотрудником информацию невозможно отозвать.
5. Владелец видит журнал решения, открытия объектов, просмотра материалов и повторной проверки: сотрудник, время, действие и ID объекта. Для подтверждения/закрытия инцидента нужно отдельное право `tenants.incident_actions`; обязательны основание и аудит, владельцу отправляется письмо. Создание и удаление магазина регулируются их отдельными административными правами.

Сотрудник в карточке клиента → «Доступ поддержки» может отменить свой запрос, пока владелец его не одобрил («Отменить»), и отправить любой свой запрос повторно («Отправить повторно»): ожидающий — повторное письмо владельцу, отклонённый/отозванный/истёкший/отменённый — новый запрос с новым номером `SUP-…` и теми же магазином, категориями, сроком и основанием.

Код и контракты: ADR 0078, `contracts/openapi.yaml`, `contracts/platform-billing-api.yaml`. При выпуске выложить backend и оба кабинета совместно, затем проверить EXT-05/06 и CLT-07/ADM-03/04/05 на тестовой организации.
