# Paddle и тарифы

- В кабинете Paddle: ссылка оплаты по умолчанию (Checkout → Checkout settings → Default payment link) — `https://business-watchdog.com/en/pay` (страница загружает Paddle.js и сама открывает оплату по `?_ptxn=…` из писем и ссылок Paddle; страница цен для этого не подходит), домен сервиса одобрен, webhook на `https://<APP_URL>/api/v1/webhooks/paddle` с секретом из `PADDLE_WEBHOOK_SECRET`.
- Paddle live checkout включён 2026-10-21. Владелец 2026-10-22 подтвердил успешный полный цикл реальной покупки подписки, отмены и одобренного Paddle возврата. ID операций и отдельный протокол прогона в репозитории не записаны. Прежняя ошибка `transaction_checkout_not_enabled` уже не считается блокером (`PROJECT_STATE.md`, Steps 217/219).
- Где взять значения (кабинет Paddle, Developer tools): `PADDLE_API_KEY` — Authentication → API keys → новый ключ, значение `pdl_live_apikey_…` (показывается один раз; `apikey_01…` в списке — это не ключ, а его идентификатор); `PADDLE_CLIENT_TOKEN` — там же, client-side token `live_…`; `PADDLE_WEBHOOK_SECRET` — Notifications → New destination (Webhook, URL выше, Usage type Platform, события `subscription.*`, `transaction.*`, `adjustment.created/updated` или «Select all») → у созданного адреса Secret key `pdl_ntfset_…` (`ntfset_01…` — идентификатор, не секрет). Для боевого режима — `PADDLE_ENVIRONMENT=production` (не `live`). Проверка: `php artisan billing:paddle-events` читает события без ошибки, неподписанный запрос на webhook получает `signature_invalid`.
- Стартовые тарифы ADR 0066 (Start, Business, Growth, Enterprise) черновиками с ценами в EUR за месяц: `php artisan billing:launch-plans <email владельца>` (в Paddle ничего не отправляет; существующие коды не трогает). Затем каждый проверить и опубликовать в `/owner/plans`.
- Тарифы, цены, периоды оплаты, лимиты и пробный период создаются в панели владельца: `/owner/plans` → «Новый тариф» → заполнить черновик → добавить цены → «Опубликовать» (причина + код из приложения). При публикации товар и цены создаются в Paddle текущего режима (`PADDLE_ENVIRONMENT`); клиентам видны только опубликованные версии.
- Доплата «частые проверки» (ADR 0041) — там же, в версии тарифа: «Интервал частых проверок, мин» (меньше интервала пакета) и цена вида «Частые проверки» для каждого периода и валюты. Клиент включает её галочкой при покупке или смене тарифа.
- Пакеты по объёму (ADR 0041) — там же, в версии тарифа: лимит «Заказов в месяц на магазин», «Льготный период при превышении объёма, дней» и «Цена индивидуально» (такой пакет публикуется без цен и на сайте показывается с кнопкой связи).
- Счета и оплаты (ADR 0043): клиент видит их в кабинете (Настройки → Подписка → «Счета и оплаты»: PDF счёта от Paddle, «Изменить способ оплаты»), владелец сервиса — в разделе «Оплаты» панели (`/owner/payments`: все платежи и итоги месяца по валютам — оплачено, налог, комиссия Paddle, остаётся нам). После выпуска этой версии один раз: `php artisan billing:paddle-transactions`.
- Возвраты (ADR 0044, 0076): в разделе «Оплаты» у оплаченного платежа кнопка «Вернуть» (владелец сервиса и сотрудник с правом биллинга) — сумма (по умолчанию весь остаток, с налогом), причина, при полном возврате возможность отменить подписку. Деньги уходят только после подтверждения владельцем сервиса с причиной и кодом из приложения. Полный возврат с отменой прекращает доступ после одобрения Paddle; частичный возврат тариф не меняет. Клиентская отмена в первые 14 дней от начала подписки запрашивает полный возврат, а после этого срока действует до конца оплаченного периода. До одобрения возврата Paddle тариф остаётся действующим. Paddle может проверить возврат сам («Проверяется Paddle»). Возвраты, сделанные вручную в кабинете Paddle, появляются через webhook `adjustment.created` / `adjustment.updated`; неопределённый ответ досверяет `billing:plan-changes`.
- Скидки — там же, вкладка «Скидки» (`/owner/discounts`): промокод, скидка выбранным организациям или акция для всех; процент или сумма; на один платёж, N периодов или навсегда; лимит использований, даты, тарифы. Создание, изменение и архив — с причиной и кодом из приложения; скидка сразу создаётся в Paddle и применяется только нашим сервером. Скидки складываются по очереди: акция → личная → промокод; перед каждым продлением `billing:plan-discounts` пересчитывает общую скидку следующего периода. Расшифровка по каждому платежу — вкладка «История скидок».
- `php artisan billing:paddle-catalog` — дозаводит в Paddle цены, которые по какой-то причине не создались (обычно не нужна).
- Только для sandbox: `php artisan billing:seed-placeholder-plans --test-prices` — черновые тарифы Free / Start / Pro с тестовыми ценами, опубликованные для проверки покупки.
