# Публичный сайт и юридические страницы

## Публичный сайт: первое наполнение

В панели владельца `/owner/site`:

- **Главная, Тарифы, Связаться с нами** есть сразу. Пока для языка не опубликован свой текст, главная показывает встроенный текст, а тарифы и форма — встроенное вступление. Тарифы и цены берутся из `/owner/plans` (только опубликованные; в тестовом режиме Paddle — с пометкой «Тестовый режим», примеры Free / Start / Pro видны только в нём).
- **Новая страница:** «Новая страница» → раздел (для вложенной, например `legal`) → адрес (slug, задаётся один раз) → меню → «Создать». Затем на каждом языке: заголовок, описание для поисковиков, HTML → «Сохранить черновик» → «Опубликовать» (с причиной). Язык без опубликованного текста отвечает 404.
- Условия, гарантии, о компании: например `legal` (без текста, просто раздел) и вложенные `legal/terms`, `legal/privacy`, `about`. В настройках страницы укажите «Юридический документ»: «Условия использования», «Политика конфиденциальности» или «Условия подписки» — именно с этими страницами клиент соглашается при регистрации и покупке, ссылка на политику появляется под формой обратной связи.
- **Регистрация** — `/{язык}/signup` (кнопки «Регистрация» и «Выбрать тариф»). Пока страницы не отмечены как «Условия использования», «Политика конфиденциальности» и «Условия подписки» и не опубликованы, согласие не спрашивается — перед продажами отметьте их (ADR 0042). Лимит регистраций с одного IP — `WATCHDOG_RATE_SIGNUP_PER_HOUR` (3 в час).
- **Публичная проверка магазина** — `/{язык}/check-store`: одноразовая диагностика публичных страниц по HTTPS URL без регистрации и без подтверждения владения. Обязательна локальная image math CAPTCHA с шумом; один normalized host/origin проверяется раз в 30 дней, один IP — один сайт за 10 дней. Проверка может один раз безопасно добавить публичный товар в корзину, но не отправляет оформление заказа, оплату, логин или регистрацию. По публичным признакам показывает осторожную подсказку платформы (WooCommerce / Shopware / неизвестно). Скриншоты и диагностика удаляются через 5 минут и не являются мониторингом, financial coverage или доказательством успешной оплаты.
- **Правка опубликованной страницы без новой версии** — в редакторе страницы, когда черновика нет: изменить текст или HTML → «Обновить опубликованную» → причина. Версия и история не меняются, прежний текст остаётся в аудите. Юридические документы (условия, конфиденциальность, подписка) так не правятся — только новой версией через черновик (согласия клиентов привязаны к версии).
- **Меню** — у каждой страницы в настройках (Сайт → Страницы → страница → «Настройки страницы»): меню (верхнее/нижнее/нет), порядок, «Подпись в меню» на ru/en/de (до 40 символов; пусто — заголовок страницы) и «Показывать под пунктом» — страница уходит в выпадающий список другого пункта того же меню, адрес страницы не меняется, вложенность — один уровень. В верхнем меню пункт с вложенными открывается списком (первым — сама страница-раздел), в нижнем вложенные идут следом за разделом. Широкое меню — с 1024 px, уже — кнопка «Меню». Подписи из репозитория: `php artisan site:page <slug> <email владельца> --menu` применяет только `menu_labels` из `database/data/pages/<slug>.php`, тексты не трогает.
- **Страницы из репозитория** — `php artisan site:page <slug> <email владельца> [--publish="причина"]` создаёт страницу редактора, если её нет (меню и порядок — из `apps/backend/database/data/pages/<slug>.php`), и сохраняет тексты en/de/ru из `database/data/pages/<slug>/*.html` как черновики, с `--publish` — сразу публикует; повторный запуск обновляет черновики той же страницы. Отдельные страницы: `videos`, `security`; девять SEO-руководств импортируются командой `site:seo-pages` (см. ниже и `../seo-guides.md`). Дальнейшие правки — в редакторе (в т. ч. «Обновить опубликованную»).
- **Страницы просмотра видео** — `/{язык}/videos/<видео>` (`checkout-check`, `payment-provider-failure`, `paid-without-money`): видео первым экраном, описание, шаги, другие видео; в `<head>` — JSON-LD `VideoObject`, в `sitemap.xml` — записи `video:`. Создаются кодом из `apps/backend/database/data/videos.php` (тексты ru/en/de, файлы, длительность, дата) — без шагов в админке. Новое видео: файлы `.mp4`/`.webp` в `apps/backend/public/videos/`, запись в `videos.php`. После выкладки — в Google Search Console для каждой страницы просмотра «Проверить URL» → «Запросить индексирование» (шаг владельца). Ссылки «на отдельной странице» на обзоре `/videos` появятся после обновления страницы `videos` из репозитория (`site:page videos <email владельца>` → публикация в редакторе; позже — кнопкой, задача 13 бэклога).
- **Решённые проблемы** — рубрика `/{язык}/solved-problems` (меню подвала) и разборы, каждый — своя страница вне меню. Данные: `apps/backend/database/data/pages/cases/<slug>.php` (тексты ru/en/de), общий шаблон `cases/render.php`, список рубрики — `cases/index.php`, страница — `data/pages/<slug>.php`. Новый разбор: добавить файл разбора и slug в `cases/index.php`, затем `php artisan site:page <slug> <email владельца>` (черновики) и `php artisan site:page solved-problems <email владельца>` (обновить список). Публикация — в редакторе или `--publish="причина"`, **только после исправления у клиента**; без названия и ссылки на магазин. Скриншоты — через медиатеку в редакторе (без данных покупателей). Первый разбор: `shopware-cart-500-time-zone`.
- **Безопасность** — `/{язык}/security` (меню подвала): что сервис читает и не делает, точные списки прав и запросов, скриншоты из кабинета и WordPress, хранение, ответы на вопросы GDPR. Начальный текст: `php artisan site:page security <email владельца> --publish="причина"`. Ссылок на исходный код (GitHub) на странице нет и быть не должно; списки прав на странице должны совпадать с кодом (`WooCommerceApiClient`, `WooCommerceApiOrderMapper::ORDER_FIELDS`, `PayPalClient::GET_ALLOWLIST`, `ShopwareApp::PERMISSIONS`, `ShopwareClient`).
- **Оформленные страницы** — если HTML страницы начинается с `<div class="bw-page"`, она выводится во всю ширину, как главная, и сама задаёт свой `<h1>` (классы — `apps/frontend/public/src/marketing-pages.css`). Картинки таких страниц лежат в `apps/backend/public/images/pages/<slug>/`: WebP 640 и 1280 px с хешем содержимого в имени (`<имя>-<хеш>-<ширина>.webp`), в HTML — `srcset`, `sizes`, `width`/`height`, `loading="lazy"`, `decoding="async"`. Caddy отдаёт `/images/pages/*` с `Cache-Control: immutable` на год, поэтому изменённая картинка — всегда новое имя файла.
- **Видео** — `/{язык}/videos`: обычная страница редактора (Сайт → Страницы → `videos`, в меню шапки). Тексты, порядок и ролики правятся там как HTML: `<video controls playsinline preload="none" poster="/videos/<имя>.webp"><source src="/videos/<имя>.mp4" type="video/mp4"></video>`. Начальный текст: `php artisan site:page videos <email владельца> [--publish="причина"]`. Файлы роликов — `apps/backend/public/videos/` в git, раздаются Caddy с перемоткой; новый ролик — H.264 с `-movflags +faststart` и обложка 1280×720, затем выкладка. Загрузить видео через редактор нельзя: медиатека принимает только картинки и PDF.
- **Карта сайта и robots.txt** — `/sitemap.xml` и `/robots.txt` строятся сами: все показываемые страницы (главная, тарифы, обратная связь на всех языках; обычные страницы — на языках с опубликованным текстом, без архивных), с языковыми версиями (hreflang) и датой публикации. Регистрация, результаты проверки магазина и оплата в карту не входят. Страница `/{язык}/check-store` с Step 306 индексируется и включена в sitemap; страницы результатов сохраняют `noindex`. Адреса берутся из `APP_URL`, robots.txt разрешает всё и указывает на карту сайта. В Google Search Console / Bing Webmaster карту можно добавить вручную: `https://<домен>/sitemap.xml`.
- **Обращения** из формы — `/owner/contacts`: статус «новое / в работе / закрыто» и внутренняя заметка; ответ — по ссылке на e-mail.

## Главная и тарифы (Step 212)

Тексты главной на ru/en/de с заголовком и описанием для поисковиков лежат в `apps/backend/database/data/home_page.php` и `database/data/home_page/<язык>.html`. Команда кладёт их в БД через панель владельца: без `--publish` — черновиками (проверить в «Сайт → Главная» и опубликовать каждый язык), с `--publish` — сразу публикует с этой причиной в аудите. Повторный запуск создаёт новую версию, прежние остаются в истории.

```sh
php artisan site:home-drafts <email владельца>
php artisan site:home-drafts <email владельца> --publish="Новая главная"
```

На сервере: `ssh -t bw-prod 'cd /opt/business-watchdog/repo/infra/production && docker compose exec -u www-data app php artisan site:home-drafts <email> --publish="Новая главная"'` — после выкладки коммита, иначе на сайте не будет стилей `.bw-page`.

Страница тарифов — в коде: `resources/views/site/marketing/pricing/<язык>.blade.php` (цены, лимиты и калькулятор берутся из `/owner/plans`, тексты FAQ и вступления — в шаблоне; при смене условий тарифов перечитать FAQ). Заголовок и описание для поисковиков — `site.pricing.meta_title` / `meta_description` в `lang/<язык>/site.php`. Стили обеих страниц — `apps/frontend/public/src/marketing-pages.css` (классы `bw-*`), собираются вместе с сайтом.

## Юридические страницы (ADR 0065)

Условия, конфиденциальность, подписка и возвраты, Impressum — страницы сайта в подвале, тексты правятся в панели владельца (Сайт → Страницы). Начальные тексты на en/de/ru кладутся черновиками одной командой (ничего не публикует, опубликованные версии не трогает; повторный запуск обновляет черновики):

```sh
php artisan site:legal-drafts <email владельца> --name="Имя Фамилия латиницей" --address="Улица дом, индекс Город, Страна"
```

Только отдельные документы — `--only=terms` (можно несколько: `--only=terms --only=privacy`); остальные страницы не трогаются. На сервере имя и адрес — те же, что в опубликованном Impressum.

Затем в панели открыть каждую страницу, проверить текст на каждом языке и опубликовать. После публикации регистрация и покупка просят согласиться с новыми версиями (ADR 0042). Тексты не проверены юристом.


## Меню футера (Step 302)

В «Сайт → Страницы» откройте страницу, в «Настройках страницы» выберите «Нижнее меню» и нужное значение «Показывать в разделе»: «Продукт», «О сервисе», «Правовая информация». При создании страницы блок также можно выбрать сразу. «Автоматически» распределяет юридические документы в правовой блок, контакты и страницу о компании — в «О сервисе», остальные — в «Продукт». «Не показывать» скрывает ссылку в меню.

«Название в меню» — отдельные поля ru/en/de, независимо от заголовка страницы; пустое поле использует заголовок. Например: заголовок «Почему Business Watchdog безопасен», название в меню «Безопасность». «Порядок»: меньшее число — выше среди ссылок одного блока; при одинаковых числах — по адресу. Сохраните настройки страницы. На сайте появляются только опубликованные языковые версии; обновление может занять до минуты из-за кеширования. На широком экране три блока стоят рядом, на мобильном — друг под другом.


## Самостоятельные разделы меню (Step 303)

В «Сайт → Страницы» блок «Разделы меню» позволяет создать раздел верхнего меню или футера: введите названия ru/en/de и порядок. Чтобы переименовать существующий раздел (в том числе один из трёх заголовков футера), выберите его в «Редактировать раздел» и сохраните изменения. Меньшее число ставит раздел выше.

В настройках страницы выберите меню и «Показывать в разделе». Один раздел можно выбрать для нескольких страниц. Кнопка «Создать раздел» открывает форму рядом с настройками и после создания сразу выбирает новый раздел; затем сохраните настройки страницы. Раздел не имеет собственной страницы и ссылки: в шапке он только раскрывает подменю, в футере показывает заголовок. Пустые разделы на сайте скрыты. Выбор раздела не меняет адрес и заголовок страницы; «Название в меню» по-прежнему задаёт подпись самой ссылки.


## Бесплатная проверка магазина `/{язык}/check-store`

Страница с формой индексируется (canonical, hreflang, в sitemap) и объясняет, что проверяется, какие ошибки находит, чем отличается от тестовой покупки и мониторинга, и ограничения (Step 306). Тексты — `lang/*/site.php`, `check_store.about`. Страницы результатов `/{язык}/check-store/<token>` остаются `noindex`.

## SEO-инструкции: девять страниц на трёх языках (Step 304)

Список URL, поисковых намерений и ограничений — `docs/seo-guides.md`. Это обычные редактируемые страницы сайта. После публикации меняйте Title, Description и HTML в «Сайт → Страницы»; H1 находится в HTML, короткая подпись ссылки — в настройках меню. Разделы WooCommerce / Stripe и PayPal / Shopware также переименовываются в админке.

```sh
php artisan site:seo-pages <email владельца>                    # первоначальные черновики
php artisan site:seo-pages <email владельца> --publish="Причина" # первая публикация
```

Без email команда выбирает первого активного владельца с активной учётной записью. Стандартный `rollout.sh` запускает команду с причиной публикации после переключения статики и перезагрузки Caddy. На новой установке без владельца `--if-owner` пропускает импорт с сообщением; после bootstrap запустите команду вручную или выполните следующий релиз.

Новый текст из репозитория (Step 306) публикуется релизом, только если опубликованная версия всё ещё совпадает с одной из ранее поставленных (`database/data/seo/shipped.php`, хеши содержимого) и у страницы нет черновика; команда выводит `refreshed`. **При изменении текстов в `database/data/seo/*.json` добавьте хеши новых версий в `shipped.php`** (дописываются в конец списка языка), иначе следующий релиз не сможет обновить их снова. Изменённая владельцем страница не трогается.

Повторный релиз не меняет опубликованные тексты, черновики с редакторскими изменениями, настройки меню, названия разделов и порядок. Снятые с публикации или архивные страницы не восстанавливаются. Без изменений могут автоматически публиковаться только исходные черновики пакета. Все 27 текстов и группы создаются транзакционно; конфликт с юридической/системной страницей отменяет импорт. Стабильные коды разделов служат только для импорта и не редактируются через API.
