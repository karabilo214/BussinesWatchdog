## Что это за проект

Business Watchdog — SaaS для обнаружения финансовых расхождений и поломок checkout в интернет-магазинах (рынок — Германия/DACH). Laravel модульный монолит + коннекторы магазинов + read-only коннекторы платёжных провайдеров + изолированный Playwright-воркер + подписка через Paddle. ИИ не реализуется.

## Ждут решения владельца

- ADR 0059 — скрипт наблюдения в плагине WooCommerce: 60 с до «зависшей» отправки (у Shopware 20 с), наблюдение без настроенной браузерной проверки. ADR 0060 — попытки оплаты при подключении через REST API: только заказы оформления (`checkout`/`store-api`), отменённый неоплаченный заказ — неудача.
- ADR 0057 подтверждён; юристу стоит подтвердить формулировку для политики конфиденциальности магазинов (скрипт наблюдения без согласия).
- ADR 0045–0049, 0051–0054 — визуальный редактор (TipTap), шаблоны блоков (встроенный набор, без цен), напоминания клиентам (получатели — владельцы, тексты без сумм), данные магазинов клиента (только владелец, только чтение), ответы на обращения (шаблоны, хранение), сводка «Сервис» (пороги, доступ owner+admin), управление сотрудниками платформы, журнал аудита, настройки и окно обслуживания приняты исполнителем, нужно подтверждение.
- ADR 0050 п. 3 — MRR сейчас по прайсу до скидок (фактическая скидка по контракту не хранится): оставить так или хранить эффективную цену.
- ADR 0009 — пороги свежести коннектора.
- ADR 0018 — суммы расхождений в обзоре.
- ADR 0020 — Stripe-коннектор (допущения).
- ADR 0021 — MFA и передача владения.
- ADR 0037 п. 3, 4, 6, 7 — коммерческие допущения смены тарифа и отмены.
- ADR 0028 — боевой аккаунт Paddle и проверка продавца (шаг владельца); налоги и юридические тексты — бухгалтер/юрист.

## Не сделано / известные пробелы

- Подписка: конверсия пробных периодов и drill-down до документов в «Обзоре», письма-напоминания об оплате, удаление заказов/платежей сверх срока хранения (сейчас только скрываются), живая проверка доплаты «частые проверки» в sandbox, одобрение возврата самим Paddle не наблюдалось (пробный возврат 1,00 € остался `pending_approval`).
- Shopware: нет архива обновления App для уже подключённых магазинов (пока магазинов с App нет).
- Наблюдение checkout: страница order-pay, статистическое правило доли успешных оплат (ADR 0007); ADR 0006 п. 2.
- Из каталога UI (`contracts/ui-api-catalog.md` §11): создание/переключение команд, maintenance windows, rules, privacy deletion; daily digest уведомлений.
- Из исследования платформ: экспорт диагностики с согласием, бюджет производительности checkout, совместимость с кеширующими/защитными плагинами; Shopify — следующая платформа по спросу.
- PayPal: настоящий подписанный webhook не проверялся.
- `spec/validate_spec.py` падает на проверке числа операций платёжного API (было до этого шага).
- Память backend-тестов растёт ~0,2 МБ на тест (лимит поднят до 512M в `phpunit.xml`, причина не искалась).
- Публичная проверка по URL (ADR 0058) теперь может выполнить одну безопасную публичную операцию add-to-cart на том же origin, но не отправляет оформление заказа, оплату, логин/регистрацию или приватные формы; для глубокой проверки всё ещё нужно подключение/верификация магазина.
- `spec/PANELS-ACCEPTANCE.md` / `spec/ACCEPTANCE.md` обновлены до Step 142; продолжать обновлять при закрытии acceptance-пунктов.
