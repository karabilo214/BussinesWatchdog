## Что это за проект

Business Watchdog — SaaS для обнаружения финансовых расхождений и поломок checkout в интернет-магазинах (рынок — Германия/DACH). Laravel модульный монолит + коннекторы магазинов + read-only коннекторы платёжных провайдеров + изолированный Playwright-воркер + подписка через Paddle. ИИ не реализуется.

## Что сделано (кратко, подробности — в `docs/progress/`)

- **Ядро** (`progress/core.md`): Docker-окружение, auth/tenancy, Sanctum SPA, магазины, pairing, подтверждение магазина (DNS, коннектор, рабочий ключ), приём событий с идемпотентностью, outbox, аудит, OpenAPI-контракт со сверкой маршрутов.
- **Сверка и инциденты** (`progress/reconciliation.md`): проекции заказов/возвратов/платежей/транзакций, allocations, 9 правил сверки, движок инцидентов, фоновая обработка, ночной проход, параллельная синхронизация и сверка (ADR 0040).
- **Коннекторы** (`progress/connectors.md`): WooCommerce-плагин и REST API (основной путь), Shopware 6 (ключ интеграции и App, 6.6/6.7), Stripe и PayPal только чтение; сквозные прогоны на настоящих sandbox.
- **Браузерные проверки** (`progress/browser-checks.md`): бэкенд, Playwright-воркер, синтетический маркер, egress-прокси, скриншоты без PII.
- **Уведомления** (`progress/notifications.md`): email, Telegram, напоминания, DKIM/SPF/DMARC.
- **Экспорты** (`progress/exports.md`): CSV findings/incidents/transactions со сроком хранения.
- **Кабинет клиента** (`progress/dashboard.md`): `apps/frontend/customer` — все экраны магазина, обзор, команда, MFA.
- **Подписка и админка** (`progress/billing.md`): тарифы и пакеты по объёму из админки, Paddle, пробный период на домен, скидки, смена тарифа и отмена, клиенты и подписки, пауза организации, доплата «частые проверки», срок хранения истории, счета и оплаты, возвраты с подтверждением владельцем, напоминания клиентам из карточки (ADR 0047), магазины клиента с находками, заказами, проверками и инцидентами (ADR 0048).
- **Публичный сайт** (`progress/public-site.md`): SSR на Blade, страницы из админки (визуальный редактор TipTap, ADR 0045; шаблоны блоков и их раздел, ADR 0046; главная редактируется со встроенного текста, «Тарифы» и «Обратная связь» — только в коде), форма обратной связи, регистрация с согласием на юридические страницы.

Тесты (Step 126): backend SQLite 539 + 4 пропущено, PostgreSQL 18 — 543/543; админка 41; кабинет 112.

## Ждут решения владельца

- ADR 0045, 0046, 0047, 0048 — визуальный редактор (TipTap), шаблоны блоков (встроенный набор, без цен), напоминания клиентам (получатели — владельцы, тексты без сумм), данные магазинов клиента (только владелец, только чтение) приняты исполнителем, нужно подтверждение.
- ADR 0009 — пороги свежести коннектора.
- ADR 0018 — суммы расхождений в обзоре.
- ADR 0020 — Stripe-коннектор (допущения).
- ADR 0021 — MFA и передача владения.
- ADR 0037 п. 3, 4, 6, 7 — коммерческие допущения смены тарифа и отмены.
- ADR 0028 — боевой аккаунт Paddle и проверка продавца (шаг владельца); налоги и юридические тексты — бухгалтер/юрист.

## Не сделано / известные пробелы

- Подписка: «Обзор» в админке с MRR и KPI, письма-напоминания об оплате, удаление заказов/платежей сверх срока хранения (сейчас только скрываются), живая проверка доплаты «частые проверки» в sandbox, одобрение возврата самим Paddle не наблюдалось (пробный возврат 1,00 € остался `pending_approval`).
- Наблюдение checkout: слой 2 (скрипт на checkout), страница order-pay, статистическое правило доли успешных оплат (ADR 0007); ADR 0006 п. 2.
- Из каталога UI (`contracts/ui-api-catalog.md` §11): создание/переключение команд, maintenance windows, rules, privacy deletion; daily digest уведомлений.
- Из исследования платформ: экспорт диагностики с согласием, бюджет производительности checkout, совместимость с кеширующими/защитными плагинами; Shopify — следующая платформа по спросу.
- PayPal: настоящий подписанный webhook не проверялся.
- `spec/validate_spec.py` падает на проверке числа операций платёжного API (было до этого шага).
- Память backend-тестов растёт ~0,2 МБ на тест (лимит поднят до 512M в `phpunit.xml`, причина не искалась).
- `spec/PANELS-ACCEPTANCE.md` / `spec/ACCEPTANCE.md` частично устарели — обновлять при закрытии пунктов.
