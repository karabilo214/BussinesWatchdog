## Что это за проект

Business Watchdog — SaaS для обнаружения финансовых расхождений и поломок checkout в интернет-магазинах (рынок — Германия/DACH). Laravel модульный монолит + коннекторы магазинов + read-only коннекторы платёжных провайдеров + изолированный Playwright-воркер + подписка через Paddle. ИИ не реализуется.

## Что сделано (кратко, подробности — в `docs/progress/`)

- **Ядро** (`core`): Docker-окружение, auth/tenancy, MFA, passkeys, доверенные устройства, магазины, pairing, приём событий с идемпотентностью, outbox, аудит (ADR 0053), «Сервис» с оповещениями (ADR 0051), окно обслуживания (ADR 0054), удаление организации (ADR 0069), доступ поддержки по разрешению клиента (ADR 0078), выкладка без простоя (ADR 0080).
- **Сверка и инциденты** (`reconciliation`): проекции, allocations, правила сверки v3 (ADR 0068; реестр FIN-01…24 — `docs/reconciliation-registry.md`), объяснения инцидентов, режимы live/test (ADR 0018), параллельная синхронизация (ADR 0040), атрибуция платежей по магазинам (ADR 0073).
- **Коннекторы** (`connectors`): WooCommerce — плагин и REST API с вебхуками (ADR 0077), Shopware 6.6/6.7 — ключ интеграции и универсальный App, Stripe (ограниченный ключ; OAuth снят) и PayPal только чтение, Stripe в Shopware; споры, multicapture и комиссии (ADR 0081–0083).
- **Браузерные проверки** (`browser-checks`): Playwright-воркер, синтетический маркер, egress-прокси, скриншоты без PII; WooCommerce и Shopware (ADR 0055), честный пропуск шага оплаты (ADR 0070).
- **Уведомления** (`notifications`): email в общем макете, Telegram, напоминания, ежедневная сводка (ADR 0067), DKIM/SPF/DMARC.
- **Экспорты** (`exports`): CSV findings/incidents/transactions со сроком хранения.
- **Кабинет клиента** (`dashboard`): все экраны магазина, обзор, права участника по разделам (ADR 0079), профиль, смена e-mail, «Моя организация», счётчики меню.
- **Подписка и админка** (`billing`): тарифы, Paddle, пробный период, скидки, смена/отмена/возврат (ADR 0076), пауза (ADR 0037), счета, напоминания (ADR 0047), действия поддержки (ADR 0048), «Обзор» с KPI (ADR 0050), сотрудники и права (ADR 0052, 0064), профиль сотрудника.
- **Публичный сайт** (`public-site`): SSR на Blade, редактор страниц, обратная связь с капчей и файлом, регистрация с согласием, юридические страницы и тарифы, проверка магазина по URL (ADR 0058), sitemap.

## Не сделано / известные пробелы

- Тестовый режим Stripe: «Stripe списал, заказ не оплачен» не ловится, пока плагин не запишет режим при оформлении (следующая версия после 0.4.1). Инцидент `CHECKOUT_FLOW_FAILED` не переносит причину шага (`payment_provider_rejected`). Матричный `browser-e2e.sh` сломан (старые имена таблиц плагина).
- Подписка: конверсия пробных периодов и drill-down в «Обзоре», удаление заказов/платежей сверх срока хранения (сейчас только скрываются), живая проверка доплаты «частые проверки».
- Наблюдение checkout: страница order-pay, статистическое правило доли успешных оплат (ADR 0007); ADR 0006 п. 2.
- Из каталога UI (`contracts/ui-api-catalog.md` §11): создание/переключение команд, maintenance windows, rules.
- §43 не реализован. Перед заявлением полного покрытия §18 нужен плановый lease на подключённом магазине.
- Эксплуатация: восстановление на новом сервере (ACC-41), нагрузочный тест (ACC-43), падение БД/Redis (ACC-10/11).
- Stripe multicapture и споры PayPal на настоящих данных не наблюдались; комиссии PayPal существующих списаний приходят с ночным `--audit`.
- PayPal Payments ограничивает выдачу client token (429) при повторных проверках с одного IP.
- Shopware: частичный возврат SwagPayPal — `unknown`. Платежи общего аккаунта без признаков магазина не разделяются (ADR 0073).
- Shopware по ключу: в кабинете нет пути добавить App, не отключая ключ, — без App нет наблюдения за оформлением (Step 280).
- Память backend-тестов растёт ~0,2 МБ на тест (лимит 512M в `phpunit.xml`).
- `spec/ACCEPTANCE.md` / `spec/PANELS-ACCEPTANCE.md` — обновлять при закрытии acceptance-пунктов.
