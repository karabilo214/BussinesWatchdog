# CLAUDE.md

Правила работы Claude Code в репозитории Business Watchdog.

## Общение

- Общаться с пользователем только на русском языке.
- В коде не оставлять комментарии, если пользователь явно не попросил их добавить.

## Порядок чтения перед задачей

1. `PROJECT_STATE.md` — текущий статус, последний выполненный шаг, что дальше. Главная точка восстановления контекста в начале сессии.
2. `AGENTS.md` — правила реализации и инварианты проекта.
3. `spec/Business-Watchdog-TZ.md` — основное ТЗ (особое внимание разделам 2, 9–14, 18–20, 25–28, 36–39).
4. `spec/database/schema.sql`, `spec/contracts/`, `spec/ACCEPTANCE.md`.
5. Для панелей/биллинга: `spec/panels/*.md`, `spec/database/platform-billing-extension.sql`, `spec/contracts/platform-billing-api.yaml`, `spec/PANELS-ACCEPTANCE.md`.
6. Реальный код, миграции и `docs/progress.md` — что фактически уже реализовано.

## Поддержание контекста

После каждой выполненной задачи обновлять `PROJECT_STATE.md` (статус, следующий шаг) и, как и раньше, `docs/progress.md` (подробная история шага) — так, как уже описано в `AGENTS.md`.

## Инварианты проекта

Полный список — в `AGENTS.md`. Ключевое, что нельзя нарушать:

- Деньги — minor units, bigint/string, никаких float и JS Number.
- Woo paid marker не является независимым доказательством capture.
- Разные финансовые сущности (charge/intent/refund/fee/payout) не смешиваются и не суммируются как одно и то же.
- Unknown/stale данные не являются нулём.
- Tenant scope обязателен в каждом service/repository/job/export/artifact access.
- Browser-проверки в P0/P1 не создают настоящую покупку и не списывают/возвращают деньги.
- Node не читает сериализованные Laravel jobs.
- Дубликаты и перестановка событий должны обрабатываться безопасно (идемпотентность).
- Screenshots/traces не должны содержать secrets и настоящие PII.
- ИИ не реализуется и зависимости для него не добавляются.

## Тесты и git

- После каждой выполненной задачи прогонять backend-тесты через PHP 8.4, установленный параллельно с основной версией через brew (`/opt/homebrew/opt/php@8.4/bin/php`), а не через системный `php` по умолчанию — composer требует `^8.3`, а системный `php` может быть более старой версии.
  Команда из `apps/backend`: `/opt/homebrew/opt/php@8.4/bin/php artisan test`.
- Коммитить и делать push после задачи только тогда, когда все тесты зелёные. Если тесты красные — сначала исправить, не коммитить незавершённое.

## Прочее

- Коммит и push делаются автоматически после каждой задачи при зелёных тестах (см. раздел «Тесты и git» выше); в остальных случаях — только по явной просьбе пользователя.
- Не писать, что протестировано с реальным Stripe/WooCommerce, если использовались только JSON fixtures.
- Не вводить незаметно новые финансовые/бизнес допущения — такие решения фиксируются в ADR (`docs/adr/`) и явно показываются владельцу.
